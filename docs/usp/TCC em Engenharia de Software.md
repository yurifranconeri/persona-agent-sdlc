# 1. Desenvolvimento Web Front‑end

A interface da web, ou seja, a parte visível e interativa com a qual o usuário se envolve, é construída por meio do desenvolvimento web front‑end. Tecnologias como HTML (estrutura), CSS (estilo) e JavaScript (interatividade) são utilizadas para criar a experiência do usuário, determinando a aparência e funcionalidades de sites e aplicações.

Essa área oferece diversas oportunidades para a realização de pesquisas destinadas ao desenvolvimento do TCC, incluindo:

*   Paradigmas de desenvolvimento front‑end
*   Padrões de projeto
*   Experiência do usuário (UX)
*   Micro front‑ends
*   Testes no desenvolvimento front‑end
*   Domain Driven Design (DDD) aplicado ao front‑end

Cada um desses tópicos apresenta desafios e possibilidades de pesquisa para aprimorar a qualidade e a eficiência do desenvolvimento web front‑end.

## 1.1 Paradigmas de desenvolvimento de software para front‑end

O desenvolvimento front‑end tem evoluído rapidamente, impulsionado por novas tecnologias e demandas de mercado. Nesse contexto, os paradigmas de desenvolvimento desempenham um papel crucial na forma como os desenvolvedores estruturam, organizam e implementam o código.

Paradigmas como:

*   Model‑View‑Controller (MVC)
*   Model‑View‑Presenter (MVP)
*   Model‑View‑ViewModel (MVVM)

facilitam a separação de responsabilidades, melhorando manutenibilidade e escalabilidade.

Frameworks modernos como React, Angular e Vue.js impulsionaram a adoção de arquiteturas baseadas em componentes, promovendo reutilização de código e modularização da interface.

### Possibilidades de pesquisa

*   Comparação entre paradigmas (MVC, MVP, MVVM, componentes)
*   Influência dos frameworks na arquitetura front‑end
*   Programação funcional e reativa no front‑end
*   Desafios na adoção de paradigmas e boas práticas

## 1.2 Padrões de projeto no desenvolvimento front‑end

Os padrões de projeto (design patterns) no desenvolvimento front‑end são ferramentas essenciais que ajudam a criar aplicações mais organizadas, manuteníveis e escaláveis. Eles fornecem soluções reutilizáveis para problemas recorrentes no desenvolvimento de software, possibilitando a adoção de práticas recomendadas pela comunidade.

Os padrões de projeto são tradicionalmente classificados em três categorias principais:

*   **Padrões criacionais**, como Factory, Builder e Singleton, que auxiliam na criação controlada de objetos.
*   **Padrões estruturais**, como Adapter, Decorator e Facade, que facilitam a composição de classes e objetos para formar estruturas maiores.
*   **Padrões comportamentais**, como Observer, Strategy e Command, que tratam da comunicação e da atribuição de responsabilidades entre objetos.

No desenvolvimento front‑end moderno, há também forte uso de **padrões de componentização**, fundamentais para organizar e reutilizar componentes de interface como menus, botões e formulários. A componentização permite a construção de interfaces complexas a partir de pequenos blocos reutilizáveis, facilitando manutenção e escalabilidade.

Outro aspecto relevante é o **gerenciamento de estado da aplicação**. Ferramentas como Redux, Context API (React), VueX (Vue.js) e MobX são utilizadas para armazenar e atualizar o estado de forma previsível, garantindo consistência da interface.

Também são aplicados padrões arquiteturais como:

*   **MVC (Model‑View‑Controller)**
*   **Clean Architecture**

Esses padrões promovem separação de responsabilidades em camadas bem definidas, facilitando a evolução do código. O roteamento e a navegação em aplicações web são viabilizados por bibliotecas como React Router e Vue Router.

As possibilidades de pesquisa nessa linha incluem:

*   Comparação entre arquiteturas front‑end
*   Implementação da mesma aplicação com diferentes frameworks
*   Aplicação de design responsivo
*   Integração de Test Driven Development (TDD) no front‑end
*   Análise de estratégias de gerenciamento de estado

## 1.3 User Experience (UX)

A experiência do usuário (UX) é uma área fundamental no desenvolvimento front‑end, voltada à criação de interfaces intuitivas, eficientes e agradáveis. Diferencia‑se da interface do usuário (UI), que se restringe aos aspectos visuais.

O processo de UX envolve etapas como:

*   Pesquisa com usuários
*   Empatia
*   Design
*   Prototipação
*   Testes de usabilidade

Essa área oferece oportunidades de pesquisa em temas como:

*   Avaliação de usabilidade
*   Design centrado no usuário
*   UX em jogos digitais
*   Ética no design
*   Neurociência aplicada à UX
*   Acessibilidade e inclusão digital

Também podem ser explorados:

*   Métricas de engajamento
*   Padrões de comportamento do usuário
*   Uso de inteligência artificial para personalização da experiência
*   Novas ferramentas e tecnologias de design

## 1.4 Micro Front‑end

A arquitetura de micro front‑end surge como alternativa às aplicações monolíticas tradicionais, dividindo a interface do usuário em módulos menores e independentes, que podem ser desenvolvidos, testados e implantados separadamente.

### Vantagens

*   Escalabilidade
*   Equipes independentes
*   Atualizações isoladas
*   Possibilidade de múltiplas tecnologias

### Desafios

*   Comunicação entre módulos
*   Consistência da experiência do usuário
*   Integração de tecnologias diferentes
*   Gerenciamento de estado distribuído

As pesquisas podem abordar:

*   Comparação entre micro front‑ends e monólitos
*   Escalabilidade e desempenho
*   Estratégias de CI/CD
*   Usabilidade e coesão da interface

***

## 1.5 Micro‑serviço Front‑end

Os micro‑serviços front‑end aplicam os princípios de micro‑serviços à camada de interface, permitindo que cada módulo:

*   Seja implantado de forma independente
*   Utilize tecnologias distintas
*   Escale conforme a demanda

Vantagens incluem isolamento de falhas e melhor organização por domínio de negócio. As linhas de pesquisa incluem:

*   Desempenho e escalabilidade
*   Deploy contínuo
*   Gerenciamento de estado
*   Experiência do usuário em interfaces distribuídas

***

## 1.6 Gerenciamento de Testes

O gerenciamento de testes é essencial para garantir qualidade e confiabilidade das aplicações. O **Test Driven Development (TDD)** propõe a criação de testes antes do código.

Conceitos importantes:

*   Pirâmide de testes (unitário, integração, end‑to‑end)
*   Ferramentas como Jest, Mocha, Jasmine e Cypress
*   Integração Contínua (CI)
*   Entrega Contínua (CD)

Temas de pesquisa:

*   Implementação de TDD no front‑end
*   Impacto do TDD na manutenção
*   Testes de acessibilidade
*   Qualidade de software

***

## 1.7 Domain Driven Design (DDD)

O Domain Driven Design (DDD) visa alinhar o desenvolvimento de software ao domínio do negócio, estabelecendo uma linguagem ubíqua entre desenvolvedores e especialistas do domínio.

No front‑end, o DDD pode ser aplicado para:

*   Representar regras de negócio
*   Integrar front‑end e back‑end
*   Modelar estado da aplicação
*   Melhorar organização e escalabilidade

Temas relevantes:

*   DDD no front‑end
*   EventStorming
*   Gerenciamento de estado baseado em domínio
*   Migração de aplicações legadas

## 2.2 Padrões de Projetos no desenvolvimento back‑end

A aplicação de padrões de projeto no desenvolvimento back‑end é essencial para criar software escalável, manutenível e confiável. Além dos padrões clássicos (criacionais, estruturais e comportamentais), o back‑end utiliza padrões específicos relacionados à arquitetura, segurança e integração.

Destacam‑se:

*   **Padrões arquiteturais**
    *   Domain Driven Design (DDD)
    *   Clean Architecture
    *   Model‑View‑Controller (MVC)

*   **Padrões de autenticação e autorização**, voltados à segurança de dados e controle de acesso.

*   **Injeção de dependência**, que reduz o acoplamento entre componentes e facilita testes.

*   **Middlewares**, que interceptam requisições e respostas para implementar logging, cache, autenticação e tratamento de erros.

Possibilidades de pesquisa:

*   Comparação entre arquiteturas back‑end
*   Impacto dos padrões na performance

## 2.5 Test Driven Development Back‑end

O Test Driven Development (TDD) no back‑end visa aumentar a qualidade e confiabilidade do código por meio da criação de testes antes da implementação.

1.  Criar teste que falha
2.  Implementar código para passar no teste
3.  Refatorar

Ferramentas comuns:

*   JUnit

*   Jest
*   Mocha
